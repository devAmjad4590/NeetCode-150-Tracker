# NeetCode 150 Tracking System

This is a simple, manual markdown-based system for tracking your NeetCode 150 progress in Obsidian.

## How to Use

### 1. Creating a New Problem Note

1.  When you start a new problem, create a new note for it.
2.  Copy the content from the `Templates/Problem Template.md` file and paste it into your new note.
3.  Save the note in the appropriate topic folder (e.g., `01 - Arrays & Hashing`). A good naming convention is `[Number] - [Problem Name].md`.
4.  Fill out the details at the top of the note (Problem Name, Number, Difficulty, Pattern).
5.  As you solve the problem, fill in the "Key Insight" and "Solution" sections.
6.  Set the first "Next Review Date", typically for the next day.

### 2. Daily Review

1.  Open the `Dashboard.md` note.
2.  Check the "Problems Due for Review" section. You will need to manually add links to problem notes here, along with their review date, to keep track.
3.  For each problem that is due, open the note and review it. Try to recall the key insight and solution without looking.
4.  After reviewing, update the "Next Review Date" in the problem's note based on the "Spaced Repetition Schedule" on the dashboard.
5.  Add an entry to the "Review Log" in the problem's note.
6.  Update the "Problems Due for Review" list on the dashboard for the next day.

### 3. Tracking Progress

-   On the `Dashboard.md` note, you can check the box next to a topic under "Progress by Topic" once you feel you have a good grasp of it or have completed all the problems in that section.

### 4. Handling Your Backlog (Previously Solved Problems)

If you have a backlog of problems you solved before starting this system, here’s how to gradually integrate them.

**Triage Your Backlog**

Categorize problems based on when you last solved them:

-   **2-4 weeks ago**: Highest priority. These are at risk of being forgotten.
-   **1-2 weeks ago**: Medium priority.
-   **Within the last week**: Low priority. These are still fresh.
-   **2+ months ago**: Lowest priority. Treat these as "cold" problems to relearn later.

**Phase-In Approach (Don't Overwhelm Yourself!)**

1.  **Week 1**: Create notes for 2-3 problems from your highest priority (2-4 week) group.
2.  **Week 2**: Add another 2-3 problems from the backlog.
3.  Continue this process until you're caught up.

**Set Initial Review Dates**

When creating notes for these backlog problems, set the "Next Review Date" as follows:

-   **2-4 weeks old**: Set the review date for sometime **this week**.
-   **1-2 weeks old**: Set the review date for sometime **next week**.
-   **Less than 1 week old**: Put it on a normal schedule (e.g., **+3 days** from when you solved it).
-   **2+ months old**: No rush. Add them to your review schedule whenever you naturally revisit that topic.

> **Quick Tip**: Prioritize adding problems you struggled with or had to look up the solution for. They provide the highest learning value.

This system is entirely manual. The goal is to be simple and require you to engage with the material actively. You can customize any of the files to better suit your workflow.
